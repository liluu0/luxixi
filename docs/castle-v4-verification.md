# 古堡 v4 场景适配与验证

模型来源：`../sanctuary/delivery/aurelia_sanctuary_v4.blend`。
浏览器资产：`public/assets/castle-battle/aurelia-sanctuary-v4.glb`。

Blender 导出使用 Y-up，游戏统一使用 0.5 倍模型尺度。关卡位置在 `src/game/castle/level.json`，防跌落边界从同一配置读取，不能单独移动模型或修改出生点。

原生入口为圆厅南侧双扇门，游戏坐标约 `[18.8, 11, 6.4]`。靠近后点击「进入王庭大殿」或按 F；内部仍使用原有 interior.js。

碰撞由缩放后的世界坐标三角面提取；保留跨越角色高度的墙面，防止相机穿入门板。静态渲染对象按材质合批，模型变换不能再次应用于合批后的几何。

## 2026-09-20 浏览器实测

- 从出生点 `[0, 10.69, 18]` 出发，横穿庭院到前庭、走上台阶到门口，持续 grounded=true。
- 门口出现进入按钮，进入后位于原有室内 `[80, 10.52, 3.5]`。
- 步行到室内出口并返回庭院，两轮验证通过。返回位置约 `[18.8, 11.00, 6.4]`，相机位于门外 `[18.8, 13.97, 12.97]`，无黑屏。
- 跳跃时 grounded=false，体力 100→88；落地后 grounded=true、体力恢复。
- 持续攻击造成敌人伤害，击杀计数 0→1，剩余敌人 12→11；敌人能追击并造成玩家受伤。
- 西侧月牙草坪存在草坪、土床和石质接缝的毫米级叠层；草坪使用深度偏移，导出后呈白色的草坪材质已恢复为深绿色并增加低对比程序纹理。
- 移除 `fine blades` 三角草叶的渲染和碰撞。这些细面在移动镜头下产生高对比闪烁，也会生成大量无意义的小碰撞面。沿西侧草坪移动连续抓帧后未再出现白底、黑色三角或深度跳变。
- 精英守卫从入口 `[18.8, 10.6, 7]` 移到 `[20.5, 10.6, 14.5]`，避免角色返回庭院时与守卫重叠并立即受伤；往返后生命保持 100。
- 移动前近景约 6020 次绘制调用；合批后测试近景约 67–145 次，实际值随视角变化。
- 浏览器错误日志为空。重载后只请求压缩后的正式 v4 资源；生产构建通过，仍存在项目原有的大包体提示。

本轮验证覆盖配置内庭院和前庭战斗区，不代表岛上所有装饰区域均可自由漫游。GLB 使用 Draco 网格压缩并在导出阶段合并静态同材质网格；最终约 4.64 MiB（4,861,440 字节），相比未压缩 v4 的约 43.51 MiB 减少约 89.3%。

## 2026-09-20 后方庭院边界修正

用户反馈庭院后方可见区域存在空气墙。检查 v4 Blender 模型后确认，后方 `V4 | Ground completion | Concentric stone terrace ring` 的连续平台延伸到运行时约 `z=29.4`，原配置却把角色和南侧碰撞墙限制在 `z=22`。

本次将庭院 `arena.maxZ` 扩至 `29`，南侧碰撞墙移至 `z=29.4`，左右碰撞墙的纵向长度从 `17` 扩至 `24.5` 并居中覆盖 `z=5.0..29.5`。角色在 `z=21.5..29.0` 逐点传送和连续后退测试中保持 grounded，超过边界后稳定停在 `z≈29`；大门交互和进入原有室内场景回归通过。

## 2026-09-21 花园后方空气墙二次修正

根据移动端截图重新核对方向后确认，玩家所说的“花园后面”是出生点向中央花园继续前进的方向，对应庭院 `minZ`，不是前一轮扩展的 `maxZ`。v4 原生正式花园在该方向延伸到约 `z=-5.5`，外圈石台继续连接后回廊庭院，连续地面延伸到约 `z=-16.5`。

本次把 `arena.minZ` 从 `5.5` 扩至 `-16`，北侧边界同步移动到 `z=-16.4`，左右边界覆盖完整的 `z=-16.5..29.5`。四面人工边界现在由 `arena` 范围自动计算，避免安全钳制、地面提取和实体碰撞墙再次不同步。

浏览器实测从旧边界前 `x=8,z=6` 持续向前移动到 `z=3.78`，成功穿过原 `z=5.5` 空气墙；逐点检查 `z=4、0、-4、-8、-10.4、-12、-14、-15.8` 均有地面，后回廊最深处可稳定落地。越界位置会分别钳制到 `minX=-12`、`maxX=24`、`minZ=-16`、`maxZ=29`。大门交互和进入原有室内场景回归通过。

## 2026-09-21 西侧露台空气墙修正

移动端截图显示，旧的庭院西侧矩形边界 `x=-12` 穿过了 v4 模型中实际存在的西侧月牙露台。模型地面在该方向延伸到约 `x=-19.25`，但只在 `z=-1.25..20.5` 范围内与核心庭院连续，不能把整个矩形地图直接向左扩展。

本次将庭院改为核心区和四段逐级收窄的西侧露台区域并集。主露台在 `z=-1.25..16.5` 可延伸到 `x=-19.25`，后段依照圆形石台轮廓逐级收至 `x=-18.25`、`x=-17.25` 和 `x=-16.25`，避免开放桥体下方的空隙。安全位置保护会保留任一区域内的位置，越界时投影到全部区域中距离最近的边缘；人工空气墙根据区域并集自动生成分段边界，原 `x=-12` 西墙只保留在露台入口之外，露台入口处不再拦截。地面碰撞提取也同步覆盖这些区域，同时没有开放西北、西南和露台末端无连续地面的角落。

浏览器实测从 `[-11,15]` 持续向左行走到 `[-13.12,14.95]`，成功穿过旧 `x=-12` 空气墙且始终 `grounded=true`。逐点检查 `[-19,8]`、`[-19,10]`、`[-19,15]`、`[-18,18]`、`[-17,20]`、`[-16,21]` 均稳定落地；继续向西会在 `x≈-19.10` 被最外沿实体边界挡住。无地面的 `[-18,20]`、`[-19,18]`、`[-18,-8]` 等位置会分别回退到最近的分段露台或核心庭院边缘。大门进入原有室内、室内出口返回庭院均回归通过。
## 2026-09-21 旧模型资源清理

当前运行时代码和关卡配置只引用 `aurelia-sanctuary-v4.glb`，旧的 `castle-sanctuary-lite.glb` 已无引用并删除，减少静态资源 2,576,292 字节（约 2.46 MiB）。角色、原有室内场景和 Draco 解码资源继续保留。
